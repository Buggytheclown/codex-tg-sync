# Done по дате добавления

Статус — принят в реализацию запросом make-plan → make-diff. Дата обсуждения — 2026-11-09.

## Цель

Пользователь открывает Done и сразу видит последние завершённые задачи и задачи,
попавшие в Done вчера или в другой конкретный день. Порядок отражает фактическое
попадание карточки в колонку.

## Требуемое поведение

1. Карточки в Done отсортированы по времени последнего перехода в эту колонку,
   от новых к старым. При равном времени порядок стабилен после обновления
   страницы и перезапуска демона.
2. Переход учитывается независимо от способа завершения — перетаскивание,
   выбор статуса в деталях, правило поллинга, завершение по мержу PR.
   Карточка, сразу созданная в Done, получает время своего создания.
3. Если карточку вынесли из Done и затем вернули, используется время повторного
   входа. В Done представлена одна карточка, в группе последнего входа.
4. Изменение описания, приоритета, привязок, состояния чата или настроек карточки
   внутри Done сохраняет дату входа. Повтор команды, оставляющей карточку в Done,
   также сохраняет эту дату.
5. Перед первым элементом каждого дня показан компактный разделитель. Сегодня
   и вчера узнаваемы по подписи, у остальных дней указана календарная дата.
   Сами группы идут от свежих к старым, внутри группы действует порядок пункта 1.
6. День означает календарный день в выбранной временной зоне. При наступлении
   нового дня подписи перегруппировываются без перезагрузки страницы. Время
   перехода хранится однозначно и переживает перезапуск.
7. Поиск показывает только группы с подходящими карточками. Пустые дни пропускаются.
8. Отбивки относятся к обычным карточкам в развёрнутой Done. Вёрстка сохраняет
   читаемость на узкой колонке, подписи доступны с клавиатуры и экранному диктору.

## Решения для реализации

- Дни определяет локальная временная зона браузера, как при отображении остальных
  дат доски. Например, около полуночи учитывается именно локальная календарная
  дата. Отдельная настройка зоны для Done не требуется.
- Подписи согласованы с языком текущего UI — `Today`, `Yesterday`, затем дата,
  например `7 Nov`. Год показывается для дат другого года.
- Хронология определяет расположение карточки в Done. Перенос из другой колонки
  помещает её наверх независимо от положения указателя. Интерфейс предлагает
  общий перенос в Done, включая существующую цель свёрнутой колонки. Он не
  изображает выбор произвольного места между карточками Done.
- Перетаскивание из Done в другую колонку поддерживается. Перестановка внутри
  Done не меняет порядок или дату входа.
- Для существующих карточек по сохранённой истории восстанавливается дата
  последнего входа. Нужны достоверные свидетельства именно этого входа;
  более раннее известное завершение не заменяет неизвестное последнее.
  Если дату установить нельзя, карточка попадает в последнюю
  группу `Unknown date` («Без даты») со стабильным порядком внутри неё.
  Время последнего редактирования и дата установки обновления не заменяют
  неизвестную дату завершения. Новый явный вход такой карточки в Done создаёт
  обычную достоверную дату.

## Надёжность и границы

- Запись нового времени входа принадлежит той же операции, которая действительно
  перевела карточку в Done. Ошибка сохранения, конфликт версии, отклонённый
  устаревший результат поллинга или повтор принятого события сохраняют прежнюю
  дату и расположение. После неуспешного перетаскивания UI восстанавливает
  исходное положение и дневную группу.
- Дата входа независима от даты создания задачи, даты завершения хода Codex,
  даты мержа PR и общего `updated_at`. При автоматическом переносе используется
  время принятого перехода карточки в Done.
- Доска получает необходимые данные для группировки вместе с обычной проекцией
  карточек. Количество запросов при обновлении не растёт с числом карточек Done.
- Существующая история доступна после перехода на новую версию. Обновление
  представления Done само по себе не переносит карточки и не запускает работу.
- Эта задача охватывает хронологию и дневные отбивки Done. Отдельная история всех
  завершений карточки, календарь и фильтры по диапазону дат выходят за её границы.

## Приёмочные сценарии

1. Сегодня в 15:00 завершили A, вчера в 18:00 — B, сегодня в 10:00 — C.
   В Done показаны `Today` с A, C и затем `Yesterday` с B.
2. Редактирование B сегодня оставляет её под `Yesterday`.
   Выход B из Done и возвращение сегодня помещает B наверх `Today`.
3. Ручной перенос, поллинг и завершение по мержу одинаково создают новую дату.
   Создание карточки непосредственно в Done также помещает её в текущий день.
4. Повтор события завершения и действие Done → Done не поднимают карточку наверх.
5. После перезагрузки, перезапуска и поисковой фильтрации порядок и даты сохраняются.
   При смене локального дня обновляются подписи `Today` и `Yesterday`.
6. Задачи со старой достоверной историей оказываются в соответствующих днях.
   Задачи с неизвестной датой находятся в `Unknown date` до нового входа в Done.
7. При переносе из другой колонки в Done цель показывает завершение целиком.
   Неуспешное сохранение возвращает карточку на исходное место.

## Исходное состояние кода при подготовке спецификации

- `ui/src/taskOrder.ts` и `ui/src/App.tsx` используют ручной `position` для всех
  колонок и предлагают вставку относительно соседней карточки.
- `internal/storage/store_tasks.go` различает `moved` с полями `from/to`,
  `reordered` и `created` с полем `column`.
- `internal/storage/store_task_outcomes.go` переводит задачи в Done по обычному
  правилу и по legacy-завершению PR. Только второй путь записывает отдельный
  `pr_merged`, обычный `polling_event` не фиксирует колонку назначения.
- `internal/model/task_cards.go` не содержит отдельного времени входа в Done.
  Общий `updated_at` меняется и при последующих правках карточки.
- ADR-035 и карта регрессий описывают существующие ручные перестановки и
  перетаскивание в свёрнутую Done. Хронология потребует согласовать с ними
  поведение целей переноса.
