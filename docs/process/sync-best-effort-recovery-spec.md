# Best-effort Sync и восстановление через off/on

Статус — требования согласованы 2026-11-07. Реализация закоммичена и установлена;
[проверки и ограничения](sync-best-effort-recovery-validation.md), полная Telegram-приёмка off/on предстоит.

## Цель

Telegram служит дублирующим представлением сессий Codex. Историю Telegram
допустимо удалить и восстановить синхронизацией. Сбой подключения одного чата
не должен останавливать подключение остальных. Восстановление должно быть
простым и понятным пользователю через уведомления в Control и `sync off/on`.

## Создание и подтверждение топика

- Используется существующий HTTP Bot API.
- Топик сразу получает обычное название чата без технических меток.
- До отправки запроса сохраняются операция, сессия Sync, целевой чат Codex
  или черновик и точное отправляемое название с учётом ограничения Telegram.
  Последующее переименование чата не изменяет название сохранённой операции.
- ID топика принимается из ответа `createForumTopic` либо события
  `forum_topic_created`. Событие проверяется по настроенной группе,
  автору-боту и точному сохранённому названию.
- По имени привязка восстанавливается только при однозначном сопоставлении.
  Учитываются все пути создания топиков этим ботом, включая обнаружение чатов,
  `/newchat` и внешние запуски, а также незавершённые и исторические операции.
- Ответ и событие могут прийти в любом порядке. Повторное подтверждение
  одного ID не создаёт вторую привязку. Уже подтверждённая привязка сохраняется
  при появлении другого кандидата с тем же названием.

## Ошибки и best effort

- При неизвестном результате создания автоматическая повторная отправка
  `createForumTopic` для этой операции прекращается. Периодический обход
  не создаёт вместо неё новую операцию в той же сессии Sync.
- Позднее однозначное подтверждение может завершить операцию. До этого
  проблемный чат остаётся неподключённым, остальные подключаются независимо.
- Тайм-аут, неоднозначность, обнаруженный дубль и другие ошибки синхронизации
  объясняются в Control с указанием затронутого чата и доступного восстановления.
  Отсутствие события не доказывает отсутствие топика.
- Один случай не порождает уведомление каждый цикл. Существенные изменения
  обновляют случай, успешное восстановление закрывает его.
- При недоступности Telegram уведомление сохраняется и доставляется после
  восстановления связи. Подтверждённые ограничения частоты запросов соблюдаются.
- Спорные топики автоматически не удаляются. Специальный интерфейс выбора
  привязок или удаления дублей в Control не требуется. Пользователь может
  пересобрать отображение через off/on и удалить оставшийся дубль в Telegram.
- Сообщение в непривязанном топике не направляется в произвольно выбранный
  чат Codex. Пользователь получает объяснение проблемы. Такое сообщение
  не запускается автоматически после последующего восстановления привязки.

## Сохранность состояния

- Операции, привязки и нерешённые случаи переживают перезапуск демона.
  Перезапуск сохраняет включённое или выключенное состояние Sync.
- Значимые события сохраняются до подтверждения их получения через
  `getUpdates`. Повторная обработка безопасна.
- Ошибка записи в хранилище не считается успешным завершением операции.
- Старые зависшие операции восстанавливаются автоматически только при
  достаточных данных. Остальные отражаются в Control.

## Выключение и повторное включение

- `sync off` прекращает синхронизацию с топиками сессий и удаляет известные
  управляемые топики и черновики. Control и Requests сохраняются.
- Выключение доступно при выполняющемся ходе, отправляющемся запросе,
  ожидании подтверждения или неизвестном результате ранее отправленной команды.
  Оно не требует завершения работы Codex.
- Работа в Codex продолжается. Выключение не вызывает прерывание хода,
  автоматический отказ или подтверждение ожидающего запроса и не останавливает
  процесс, необходимый для продолжения работы. Ожидающие действия остаются
  доступны через Codex.
- Уже отправленные команды не повторяются и не отменяются из-за выключения.
  После перехода в off новые команды из топиков не принимаются и не отправляются.
  Состояние принятой команды сохраняется в объёме, необходимом для исключения
  повторного выполнения и выяснения результата ранее начатой отправки.
- Ошибка удаления не включает Sync обратно. Удаление остаётся ожидающим
  очистки, повторяется штатным механизмом и отражается в Control.
- `sync on` начинает новую сессию отображения и подключает актуальные чаты
  по существующим правилам отбора. В топики попадают последний запрос,
  текущий статус и доступный последний результат.
- Старые события, сообщения, кнопки и доставки не могут изменять новую
  привязку или запускать работу в новой сессии Sync. Неоднозначность между
  старой и новой операциями с одинаковым названием отражается в Control.
- Если форма `sync off --force` сохраняется ради совместимости, она также
  должна соответствовать правилу продолжения работы Codex. Явное прерывание
  работы остаётся действием `/stop`.

## Границы восстановления

Bot API не предоставляет перечисление всех топиков. Если потеряны и ответ
на создание, и событие, демон может не узнать ID созданного топика. Off/on
удаляет известные управляемые топики. Неизвестный оставшийся топик пользователь
удаляет вручную. Такая ситуация допустима в рамках best effort.

Эта спецификация заменяет прежнее требование общей паузы после неизвестного
результата создания из ADR-033 и прежнюю семантику отказа/drain при выключении.
При реализации связанные контракты и проверки должны быть приведены в
соответствие с этими согласованными требованиями.

## Приёмка

1. Потерянный ответ на создание восстанавливается через однозначное событие.
2. Оба порядка прихода ответа и события, повтор события и перезапуск между
   ними приводят к одной привязке.
3. Одинаковые и обрезанные названия, поздние события и события других путей
   создания не приводят к ошибочной привязке. Неоднозначность видна в Control.
4. Неизвестный результат одного создания не блокирует остальные чаты
   и не вызывает автоматических повторов этой операции после перезапуска.
5. Off/on во время работы, ожидания подтверждения и неопределённой отправки
   пересобирает Telegram-представление без прерывания, автоматического решения
   запросов или повторного исполнения команд в Codex.
6. Ошибки удаления и перезапуск в состоянии off сохраняют выключенный Sync
   и возможность очистки. Старые доставки и кнопки не действуют в новой сессии.
7. Живая проверка искусственно потерянного HTTP-ответа подтверждает получение
   события создания и восстановление привязки на используемом контуре.
