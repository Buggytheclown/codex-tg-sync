# Создание Task из Трекера и именование чатов Codex

Спецификация от 13 ноября 2026. Цель — пройти от готового тикета до первого собственного сообщения в чате без ручного переноса названия, ссылок и настроек. Для чата исправлений того же ПРа доска также выставляет имя в Codex. Исходный процесс описан в [карте задачи](task-review-journey.md).

## Создание карточки

В форме новой Task первым полем для ввода, над названием, показывается тикет Трекера. Можно вставить ключ `TASK-42` или ссылку на задачу. По распознанному ключу доска один раз запрашивает название. Если поле названия пусто, в нём появляется точный `summary` тикета. Пользователь может его отредактировать. При сохранении создаётся одна Task в TODO с выбранным названием и ссылкой на тикет.

Ручное название имеет приоритет, в том числе если его ввели во время запроса. Смена тикета заменяет ранее подставленное значение, пока пользователь его не редактировал. После очистки ссылки или смены тикета запоздалый ответ игнорируется. При недоступности Трекера, отсутствии прав или неизвестном ключе форма сохраняет ввод и предлагает повторить чтение либо ввести название вручную. Task по-прежнему можно создать без тикета. Чтение выполняется при вводе тикета, без фонового опроса. Демон извлекает ключ и обращается к настроенному Трекеру, передавать авторизацию на адрес из вставленной ссылки не требуется.

## Новый чат разработки

В Task без привязанного чата рядом с привязкой существующего доступно действие «Создать чат». Оно создаёт именованный чат в каталоге `agents` с моделью по умолчанию из локального конфига и привязывает полученный `threadId` к этой Task. Пользователь попадает в этот чат в Desktop. Создание чата завершается с нулём ходов. В приложении пользователь дописывает задание и сам впервые нажимает «Отправить».

При первом открытии чата с тикетом в редактируемое поле подставляется каноническая ссылка. Для открытия используется ссылка на конкретный чат с URL-кодированным параметром `prompt`. Повторное открытие использует обычную ссылку на тот же чат и сохраняет уже набранный черновик. Если версия Desktop не поддерживает подстановку, доступна команда «Скопировать ссылку на тикет». Если ОС не открыла приложение, в карточке остаётся действие «Открыть в Codex».

Двойное нажатие и повтор после потери ответа должны приводить к одной привязке. Когда ID уже получен, ошибка именования, открытия или сохранения привязки восстанавливается для этого ID. При неизвестном результате создания доска сообщает о неопределённости и позволяет привязать найденный чат. Автоматический повтор создания допустим только при известном отсутствии чата. Неверный каталог или недоступная модель показываются пользователю.

## Имена в конфиге и чат фикса

В локальном конфиге демона хранятся два отдельных шаблона, путь к рабочему каталогу для чата разработки и модель по умолчанию. Персональные значения остаются в конфиге установки. Префиксы и порядок частей можно менять без сборки. Изменения применяются при последующем именовании. Согласованные шаблоны по умолчанию — `ПР {ticket} {title}` и `Фикс {ticket} {title}`. В обоих случаях `ticket` — ключ тикета Task, а `title` — полное сохранённое название этой же Task, включая ручную редактуру. Проект уже входит в название карточки. Для названия «Проект Исправить выгрузку» результат — `ПР TASK-42 Проект Исправить выгрузку` и `Фикс TASK-42 Проект Исправить выгрузку`. При создании чата разработки из Task без тикета предлагаем пропускать пустую часть шаблона и лишний пробел.

Поллер `PR feedback` сохраняет существующие правила запуска и подтверждения. Когда он создаёт чат исправлений и известна родительская Task, доска применяет шаблон фикса к **чату Codex**. Повторный раунд использует тот же чат и сохраняет ручное переименование. Роль определяется типом карточки и источником запуска. Чат разработки, запуски для ревью чужих ПРов и привязанные вручную сторонние чаты не требуют переименования.

Родительскую Task пользователь часто привязывает уже после первого запуска фикса. Предлагаем тогда оставить ПРу исходное имя до привязки и применить шаблон, когда известны и тикет, и ID чата. Если при привязке у чата уже есть имя и его происхождение неизвестно, сохранить имя и показать «Применить шаблон». Пользователь подтвердил это правило. Сбой именования виден на карточке и допускает повтор для того же ID. Запуск и работа над ПРом продолжаются независимо от наличия названия.

## Техническая проверка

| Возможность | Что проверено | Что предстоит проверить при реализации |
|---|---|---|
| Название тикета | Живой read-only вызов Tracker `get_issue` вернул ключ и `summary` без комментариев. Текущий API создания Task уже принимает `ticket_url`, форма пока отправляет только название и параметры карточки. | Авторизацию чтения из окружения установленного демона, включая понятную ошибку при недоступности. |
| Именованный чат без хода | Изолированный тест на CLI 0.167.1 и на App Server из Desktop 26.1106.51428. После `thread/start(cwd, model)` и `thread/name/set` получены ожидаемые каталог и модель. После перезапуска `thread/read` вернул сохранённое имя и ноль ходов. В поставке Desktop дополнительный `thread/resume` восстановил каталог и модель, число ходов осталось нулевым. | Действие из Task, устойчивую привязку и выбор той же модели в Desktop для первого сообщения. Существующему Go-вызову старта нужно передать модель. |
| Ссылка в поле ввода | Обработчик установленного Desktop принимает `codex://threads/<id>?prompt=<encoded-ticket-url>` и передаёт этому чату `prefillPrompt` и фокус ввода. | Открыть из браузера доски, увидеть и отредактировать ссылку, убедиться в отсутствии отправки до нажатия пользователем. Это поведение конкретной сборки Desktop. |
| Имя чата фикса | Диспетчер знает точный ID созданного чата, клиент уже поддерживает `thread/name/set`, родительская связь хранится отдельно. | Проверить оба порядка событий — сначала чат или сначала связь — и возврат к тому же чату на новом раунде. |
