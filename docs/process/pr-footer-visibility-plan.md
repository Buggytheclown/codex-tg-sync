# Видимость доски: план обновления футеров

> Superseded 2026-11-13 by [shared Arcanum reads](shared-arcanum-reads-spec.md).
> The former browser-presence requirements below are historical.


Дата: 2026-11-11. Основание: `pr-footer-visibility-spec.md`.

## Решение

Один существующий последовательный metadata worker сохраняется. Перед выборкой
и каждым новым чтением он проверяет общее разрешение от видимых страниц.
Рабочие поллеры не используют это разрешение.

Браузер посылает `POST /v1/board-presence` с `client_id`, возрастающим `sequence`
и `active`; `refresh` используется только при восстановлении связи. Идентификатор создаётся на время подключения компонента, не хранится
в localStorage и не является идентификатором пользователя. Видимая страница
продлевает разрешение каждые 10 секунд; скрытие, pagehide и размонтирование
отзывают его. pageshow/online возобновляют передачу только для видимой страницы.
Фокус не используется. Восстановление SSE также обновляет разрешение, только
если страница видима. Запрос ограничен пятью секундами; отзыв использует
keepalive. Ответ не меняет пользовательские данные.

В памяти демона хранится ограниченная таблица (не более 1024 записей) с последней
последовательностью, активностью и сроком 45 секунд. Повторные и опоздавшие
номера игнорируются, включая продление, пришедшее после отзыва. Неактивные
записи сохраняются до истечения срока для защиты от перестановки запросов.
Истёкшие записи удаляются; SQLite и миграция не нужны. Без heartbeat новые
чтения запрещены не позднее чем через 45 секунд от последнего принятого
сигнала. Текущее чтение может завершиться в пределах существующего timeout.
Endpoint использует действующие Host/Origin/JSON/body-limit проверки API.

При переходе общего состояния 0 → 1 фиксируется время активации и будится worker.
При online, восстановлении SSE после ошибки или успешном повторе после ошибки
heartbeat отдельный refresh также будит worker и инициирует обход; повторные
запросы объединяются с незавершённым обходом.
Он выбирает PR с истёкшим next_check_at либо с last_attempt_at раньше активации.
Это позволяет обновить недавно проверенные PR, сохранив ограниченные SQL-выборки
по 10 и двухсекундные паузы. Метка незавершённого обхода сохраняется в памяти
worker через паузу: быстрые возвращения не ставят вторую копию очереди. После
опустошения обхода следующая активация создаёт новую метку. Начавшееся чтение
считается частью текущего обхода; повторно его ставить не нужно.

Сигнал пробуждения объединяет уведомления, а состояние перечитывается под mutex.
Один worker исключает параллельное чтение одного PR. Обычная проверка сроков
остаётся раз в 10 секунд; отсутствие активности не блокирует реакцию на
активацию. Продление видимой страницы после перезапуска демона восстанавливает
разрешение без перезагрузки UI.

## Альтернативы

- Остановить только browser refetch недостаточно: запросы в Арк делает демон.
- Привязать активность к SSE-соединению недостаточно: скрытая вкладка сохраняет
  соединение, а потерянное соединение может обнаруживаться неопределённо долго.
- Передать browser прямое чтение Арка усложняет границу доступа и дублирует
  существующий reader. Короткое разрешение в памяти решает задачу без этого.

## Порядок и проверка

1. Тесты разрешения: начальное отсутствие, несколько вкладок, переходы,
   истечение срока, перестановка/повтор сигналов, ограничение размера.
2. Тесты worker и storage: отсутствие IO на паузе, немедленная активация,
   свежий кеш при возвращении, остановка посреди batch, сохранение очереди,
   pacing, ошибки и отмена. Расширить выборку необязательной меткой обхода.
3. Добавить защищённый endpoint и связать один объект разрешения с API и worker
   при запуске приложения. Тестировать успешный HTTP путь и trust boundary.
4. Отдельный UI hook и тесты visibilitychange, pagehide/pageshow, online,
   heartbeat, ошибок, размонтирования и отсутствия реакции на blur/focus.
5. Go targeted + race, полный go test/build, UI test/build, diff/приватные данные.
   Обязательное свежее ревью согласно AGENTS.md; устранить замечания.

Ни новый dependency, ни схема, ни новые настройки пользователя не нужны.
Визуальный стиль не меняется. Реальный браузерный сценарий следует проверить
при доступном browser host; отсутствие этой проверки обозначить в результате.

## Результат реализации и проверки

Реализовано в локальном diff: общий объект разрешения API/worker, ограниченная
таблица с TTL и sequence, выборка по метке обхода, lifecycle hook и восстановление
через online/SSE. Схема SQLite и рабочие поллеры не менялись.

Проверки: полный Go test/build, race для arcanumreview/controlapi/storage,
221 UI test и production UI build. Дополнительно добавлены backend-тесты refresh
и сквозная проверка handler → worker → SQLite с синтетическими данными. Свежее
ревью не выявило ошибок; замечание о недостающих backend-тестах refresh закрыто.

Browser access host недоступен: реальная проверка скрытия вкладки/сворачивания
окна не выполнена. Код ещё не установлен в работающий демон; коммит/пуш не сделаны.
