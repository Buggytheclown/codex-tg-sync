# Фильтр доски по типу карточки

Дата: 2026-11-11. Объём: локальная фильтрация UI, без изменения данных и API.

## Поведение

- Рядом с поиском появляется один ChipSelect текущего дизайна: All types / Task /
  PR / Schedule. По умолчанию выбраны все типы. Schedule включён как существующий
  самостоятельный тип. Sources остаются в боковой панели и не фильтруются.
- Выбранный тип и текстовый поиск применяются одновременно ко всем колонкам,
  включая открытую Done. Порядок карточек и группировка Done по дням сохраняются.
  Счётчик каждой колонки показывает отфильтрованные карточки. Общий счётчик
  в заголовке, как при поиске, остаётся числом всех незавершённых карточек.
- Фильтруется самостоятельная карточка. Однострочные связанные PR под Task
  сохраняются независимо от выбранного типа и поиска, как существующие связи.
  Они открывают детали PR, даже если его самостоятельная карточка отфильтрована.
- Открытые детали и несохранённые правки сохраняются при смене фильтра.
  Фильтр не меняет тип, статус, очередь, чат, историю или запросы запуска.
- Выбор действует в текущей открытой странице, аналогично поиску; после
  перезагрузки снова All types. Отсутствующий тип в старых UI-данных трактуется
  как Task, как в существующем отображении карточки.
- Во время перетаскивания выбор типа недоступен, чтобы не скрыть переносимую
  карточку. Цветовая схема и существующие элементы управления сохраняются.

## Проверка

На доске с Task, PR, Schedule и Source каждый выбор показывает только нужные
самостоятельные карточки; All types восстанавливает все. Поиск дополнительно
сужает выбор. Done фильтруется с сохранением отбивок. При Task-фильтре связанный
PR остаётся кликабельным и открывает свой чат/детали. Смена фильтра сохраняет
выбранную карточку и черновик; запросов на изменение задач нет. Селект использует
существующие доступные роли и клавиатурное управление ChipSelect.


## Реализация и проверка

Реализовано локально через существующий ChipSelect и фильтр compact-карточек.
Новых зависимостей, серверных запросов и изменений схемы нет. Проверяются общий
набор UI-тестов и production build. Свежее ревью выявило закрытие деталей по
pointerdown на фильтре; узкое исключение исправляет это, регрессионный тест
подтверждён снятием/возвратом исправления. Browser host недоступен, поэтому
визуальная проверка в настоящем браузере остаётся невыполненной.
