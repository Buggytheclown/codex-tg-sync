# Local task board implementation brief

Build a personal local kanban inside codex-tg. SQLite owns tasks, polling configuration, source-owned child definitions, events and launch requests; App Server owns chat execution. First version supports Arcanum PRs, cron and manually linked chats. Release monitors are deferred.

UI: collapsible compact source list on the left; Inbox, TODO, Polling, Done in the center; selected card details/settings on the right. Done is hidden by default; Show/Hide Done toggles its visibility and remembers the preference in browser storage. This does not change task state or the available move destinations. Sources are ordinary tasks whose repeat polling action creates other tasks. Task execution is a separate optional running/completed projection. Reading a card does not move it. No browser approval or extra notifications.

One task spans one PR cycle. A source atomically creates an Inbox task, copies its owned child definition and queues a frozen Telegram launch request. Each new child title starts with the source’s current name. The default review source is PR review; an exact old Assigned PRs name is upgraded once, preserving custom names. Cron titles add the scheduled local date/time and timezone immediately after the source prefix; a configured child title follows it. Historical task display names remain unchanged. A source owns title, initial and one continuation prompt, execution settings, and optional inactive child waiting settings. Source edits affect future tasks only; existing ordinary tasks remain self-contained. No separate Templates entity, shared relation, selector or version UI exists. The source detail page shows trigger/on-off/diagnostics and the task to create, with title/prompt/CWD always visible and model/reasoning compact. Polling is enabled solely by the Polling column plus valid configuration. Once polling returns the same task to Inbox; after completion/ship it never rearms automatically. Conditions use ANY; empty comment sets never trigger.

Use tasks, task_polling and task_events. Legacy template tables may remain inert; migrate source definitions atomically from referenced templates, not unused source config. Add task/event/target-thread linkage and frozen execution settings to external requests. Version and generation guards reject stale writes/checks. Event acceptance, child definition copy, task transition and request insertion share one transaction. Preserve old database contents, historical task configs, frozen requests and legacy dedup barriers. Import PR/cron sources once and run only the new owner afterward. New source tasks use an explicit initial launch policy: manual by default, trusted PR authors, or automatic. Continuations require Telegram Start. Every automatic initial request must appear in Telegram before claim. The once-only imported review-source upgrade restores the configured legacy review author allowlist if no explicit board policy exists; it does not enable feedback or existing cron sources automatically. Fresh cron imports retain their configured manual/auto policy. Frozen requests preserve their existing policies.

Manual chat additions start in TODO and are idempotent by thread ID. TODO/Done cancel definitely unstarted requests under the same launch gate as claim/dispatch; active or ambiguous work is not replayed or interrupted. Busy continuation stays pending for another explicit Start after completion. Continuation must authoritative-read and start only the same target thread, never steer or replace it. Preserve Sync restart behavior.

PR baseline is the last accepted event/instruction, not a claim that an LLM reviewed a revision. Preserve changes between a pass and rearming. Verify actual Arcanum command/JSON contracts before implementing comments/revisions. A PR wait with complete_on_merge enabled moves Polling to Done after an authoritative merged PR observation. Generated PR review and PR feedback waits default to enabled, including legacy waits with no explicit option; manual/cron waits default to disabled. An explicit false preserves waiting. Closed-but-unmerged PRs and source pollers retain their existing behavior.

Extend the shared snapshot producer to topics union tracked task threads, including Sync off/topic expiry. React/TypeScript/Vite lives in ui; Go serves explicit static directory and existing controlapi routes. HTTP commands and SSE invalidation/refetch; reconnect/focus/periodic reconciliation closes notification gaps. Write routes ship with exact loopback Host, same-origin and JSON guards; no wildcard CORS.

Implementation order: capability spike; storage/domain and published DTO; UI/API and Go pollers; daemon integration and explicit add-chat skill; full validation; fresh Sol review and fixes before commit; separate Sol E2E/regression check. No push. Test meaningful transactions, old DB import, cancellation interleavings, busy/missing continuation, empty/ANY PR conditions, cron occurrences, projection without topics, browser flows and existing Telegram regressions. Use dedicated QA data for live checks.

Launch cards show the actual PR author in From and the source name in Source. Author provenance is durable independently of optional child waiting settings. Initial and continuation request prompts are exactly the configured text after one-pass placeholder rendering; polling facts remain in task_events, without a forced facts appendix. External permission defaults are taken from configuration when child execution settings are saved.

Task drag moves support reordering inside a column and insertion between cards across columns. A visible dashed placeholder previews the release position, and the original card is dimmed and marked Moving. The optimistic order has an explicit saving state, survives deferred board refreshes and rolls back on failure. Neighbor-based atomic insertion handles historical equal positions; same-column reorder never rearms polling or cancels launch requests. Native browser visual/drag QA remains required separately when an enabled browser surface is available.

Board refreshes and SSE use compact summaries; full task/source details load only on selection with loading/error/retry and stale-response guards. Same-column ordering is a dedicated local reorder-only transaction, independent of Sync and launch locks. Creation and column moves no longer wait for unrelated background Sync; column transitions still serialize with active external dispatch.

Ordinary tasks expose Overview (editable title/description/priority and connections), Polling (source URL, prompts/execution, waiting conditions) and History. Overview uses a readable task brief and omits polling summaries, dates and launch-request/frozen-prompt readback; Polling and History retain their existing roles. There is no separate Settings tab. Source URL is the provenance link; PR ID selects the monitored PR. The workflow inspector uses one atomic save for prompts and waiting settings, preserving draft/version conflict protection; activation remains an explicit subsequent move. See [the workflow brief](task-workflow-ui-brief.md) and [shared visual design](shared-board-design-brief.md).

Overview title, description and priority autosave on field blur with saving/error feedback and retained drafts across navigation; there is no ordinary Save overview button. Cmd+Enter remains an optional flush and saves other focused detail forms. See [the autosave brief](overview-autosave-brief.md). Overview can attach an existing Codex chat and shows its deep link; linked dashboard cards expose Open in Codex. Task priority low/normal/high is stored and edited in Overview or the single card priority control, independently of manual order. Linking observes existing authority only and rejects ambiguous launch/binding conflicts.

Ordinary board cards also edit priority directly and always show a Codex control: linked chats open through the deep link; unbound cards visibly offer an inline chat-ID/deep-link attachment form. These controls are siblings of the draggable card-selection button. Priority changes use a compact metadata-only command and preserve task order, settings, polling runtime and launch requests. Inline actions preserve detail drafts and never promote a stale full editor to a newer external version.

Each ordinary task may store one external ticket URL, independently of its PR/source URL and Codex chat. Cards and Overview open the saved HTTP(S) link or let the operator add, edit or clear it. This is passive metadata: no tracker API, ticket creation, status synchronization, notifications or polling behavior. A compact versioned metadata command preserves all other task fields and runtime; legacy saves omitting ticket_url preserve the link.

Ticket controls display the last nonempty URL path segment, with the full destination as href/tooltip. Operators can enter a tracker key such as TASK-123; storage normalizes it to the full HTTPS tracker URL. Full URLs remain supported and source provenance is unaffected.

Arcanum identity comes from the daemon configuration for PR discovery and tracking own comments. Forms do not expose a login editor. PR waits expose a separate Move to Done when PR is merged checkbox, including source-owned child waiting settings. Merge completion never launches a model and is independent of ANY wake conditions. Source edits apply to future children; existing task options remain independent.
